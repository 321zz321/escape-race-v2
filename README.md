# משחקי הבינה — מרוץ הבריחה

## 1. מה זה

ארבעה סוכני בינה מלאכותית מתחרים במקביל על יציאה מארבעה חדרי בריחה: מעבדה, מחסן, שדה מוקשים וכספת.
הקהל רואה בדפדפן ארבע זירות בתלת־ממד, את הפעולות של הסוכנים ואת ההסברים שלהם בעברית.
המנחה מחבר את המתמודדים ומזניק את המרוץ, ובוטים ממלאים את המקומות הפנויים כדי שתמיד יהיו ארבעה משתתפים.

## 2. הרצה במחשב

צריך להתקין Node.js ו־npm, שמגיע איתו. פותחים חלון פקודות בתיקיית הפרויקט ומריצים לפי הסדר; ההתקנה נחוצה בפעם הראשונה ואחרי שינוי התלויות:

<div dir="ltr">

```sh
npm install
npm start
```
</div>

אם PowerShell חוסם הרצת סקריפטים, משתמשים ב־`npm.cmd install`, ב־`npm.cmd start` וב־`npm.cmd test` בהתאמה.

משאירים את החלון פתוח. ברירת המחדל היא פורט `3000`, ובהפעלה יודפסו:

- **מסך הצפייה:** `http://localhost:3000/?mode=live` — זה המסך שמציגים בשידור.
- **עמדת המנחה:** `http://localhost:3000/host?admin=<ADMIN_KEY>` — מעתיקים את הקישור המלא שהודפס, כולל המפתח האמיתי.
- **חיבור הסוכנים:** `http://localhost:3000/mcp`, וגם קישור אישי וכותרת הזדהות לכל מתמודד.

יודפסו גם מפתח המנחה, הגדרות הקצב ומספר הבוטים. חלון הפקודות מכיל מפתחות סודיים; אין להציג אותו בשידור.

**הדגמה בלי סוכנים:** פותחים `http://localhost:3000/?mode=demo&seed=42&speed=1`. הדגמה רצה בתוך הדפדפן ואינה מושפעת מכפתורי המנחה. `seed` הוא מספר או טקסט שקובע את החידות; אותו ערך משחזר את אותה הדגמה. `speed` מקבל `1`, `2` או `4` למהירות רגילה, כפולה או פי ארבעה. בלי `mode=live` נפתחת הדגמה; בלי `seed` נבחר ערך אקראי. נדרש חיבור לאינטרנט לטעינת ספריית התלת־ממד והגופן.

**הגדרות לפני ההפעלה** — משתני סביבה הם ערכים שמגדירים בחלון הפקודות לפני `npm start`:

| משתנה | ברירת מחדל | מה הוא משנה |
| --- | --- | --- |
| `PORT` | `3000` | מספר הפורט; כל הכתובות ישתמשו במספר שבחרתם. |
| `ADMIN_KEY` | מפתח אקראי חדש בכל הפעלה | המפתח הסודי של עמדת המנחה; אפשר לקבוע מפתח קבוע, ארוך ואקראי. |
| `PACE` | `1` | מכפיל את זמני ההמתנה בשרת לכל המשתתפים, כולל זמני הבוטים. `0.5` מקצר לחצי; `2` מכפיל. |
| `BOT_SPEED` | `1` | מכפיל נוסף לזמני הבוטים בלבד: קטן מ־1 מאיץ, גדול מ־1 מאט. |
| `AUTO_START` | כבוי | רק הערך `1` מזניק מיד בהפעלה; אחרת מחכים בלובי למנחה. |

הערכים של `PACE` ו־`BOT_SPEED` חייבים להיות בין `0` ל־`100`; לשידור רגיל השאירו `1`. הם אינם משנים את ההדגמה המקומית בדפדפן.
לדוגמה, ב־PowerShell, להפעלה בפורט אחר עם מפתח מנחה אקראי:

<div dir="ltr">

```powershell
$env:PORT = "3001"
$env:ADMIN_KEY = node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
$env:PACE = "1"
$env:BOT_SPEED = "1"
$env:AUTO_START = "0"
npm start
```
</div>

ההגדרות נשארות בחלון הזה. בדוגמאות בהמשך החליפו `3000` בפורט שבחרתם. לעצירה לחצו `Ctrl+C` בחלון השרת.

**אחרי שינוי `public/engine.js` חייבים לעצור ולהפעיל מחדש את השרת, ואז לרענן את מסכי הצפייה.** השרת והצופים מריצים את אותו מנוע משחק; גרסאות שונות עלולות להציג מצבים שונים.

## 3. ניהול הערב

לפני ההפעלה יוצרים את `server/contestants.json` (מעתיקים את `server/contestants.example.json`; הקובץ האמיתי לא עולה ל־GitHub כי יש בו מפתחות) ועורכים אותו: רשימה של עד ארבעה מתמודדים. `name` הוא השם שיופיע בשידור, `color` הוא צבע בפורמט `#RRGGBB`, ו־`key` הוא מפתח אישי ייחודי. דוגמה למבנה בלבד:

<div dir="ltr">

```json
[
  { "name": "Player 1", "color": "#ff7a45", "key": "REPLACE_WITH_A_LONG_RANDOM_KEY" }
]
```
</div>

החליפו את מפתחות ההדגמה שבקובץ במחרוזות אקראיות ארוכות. הפקודה הבאה מייצרת מפתח בן 64 תווים; מריצים מחדש לכל מתמודד ומעתיקים את התוצאה לשדה `key` שלו:

<div dir="ltr">

```sh
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
```
</div>

שינוי הקובץ נכנס לתוקף רק אחרי הפעלה מחדש של השרת. מקומות שלא הוגדרו ברשימה מתמלאים בבוטים עם ההזנקה; מתמודד רשום שלא התחבר שומר את מקומו ולא מוחלף בבוט. רשימה ריקה, `[]`, נותנת ארבעה בוטים.

1. **לובי:** השרת עולה במצב המתנה. בעמדת המנחה אפשר ללחוץ **„פתיחת לובי חדש”**; בשדה „זרע” מכניסים מספר או טקסט למרוץ חוזר, או משאירים ריק להגרלה. פתיחת לובי חדש מוחקת את המרוץ הקודם.
2. **חיבור:** מעתיקים מאזור „חיבור המתמודדים” את הקישור האישי לכל מתמודד. אפשר להתחבר ולראות את הכלים כבר בלובי; ניסיון לפעול יענה שהמרוץ עוד לא התחיל.
3. **הזנקה:** כשהמתמודדים מוכנים לוחצים **„התחלת המרוץ”** ומודיעים להם להתחיל לפעול. הבוטים מתחילים אוטומטית.
4. **סבב נוסף:** **„איפוס והגרלת מרוץ”** מבטל את המרוץ הנוכחי, מוחק את התקדמותו ומחזיר ללובי עם זרע אקראי חדש, גם אם כתוב משהו בשדה הזרע. לוחצים שוב „התחלת המרוץ” כשמוכנים.

## 4. איך מתמודד מחבר את הסוכן שלו

המנחה מוסר **כתובת MCP ומפתח אישי**. בדוגמאות מחליפים את `<URL>` בכתובת המלאה שמסתיימת ב־`/mcp`, בלי פרמטרים, ואת `<KEY>` במפתח, בלי הסוגריים הזוויתיים. לדוגמה מקומית: `http://localhost:3000/mcp`. במחשב אחר משתמשים בכתובת הציבורית מסעיף 5; `localhost` מתייחס תמיד למחשב שבו רץ הלקוח.

**Claude Code:** בחלון הפקודות מריצים את הפקודה, פותחים `claude` באותה תיקייה ובודקים את החיבור עם `/mcp`. [הוראות Claude Code](https://code.claude.com/docs/en/mcp).

<div dir="ltr">

```sh
claude mcp add --transport http escape-race "<URL>" --header "Authorization: Bearer <KEY>"
```
</div>

**Claude Desktop — דרך ההגדרות:** נכנסים ל־`Settings > Connectors`, בוחרים `Add custom connector` ומדביקים `<URL>?key=<KEY>`. בגרסאות חדשות המסלול הוא `Customize > Connectors > + Add`. בוחרים `No sign in` אם נשאלים, ומפעילים את המחבר בשיחה. כאן נדרשת כתובת ציבורית: החיבור מגיע מהשרתים של Anthropic גם כשמשתמשים באפליקציית המחשב. [הוראות המחברים](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp).

**Claude Desktop — דרך קובץ הגדרות:** אפשר להשתמש בגשר `mcp-remote`. פותחים `Settings > Developer > Edit Config`, וב־`claude_desktop_config.json` מוסיפים את הרשומה הבאה ל־`mcpServers` הקיים (או משתמשים בדוגמה כקובץ חדש). נדרשים Node.js ו־npm גם במחשב המתמודד. זו הפעלה של `npx mcp-remote <URL> --header "Authorization: Bearer <KEY>"`; בדוגמה המפתח עובר דרך משתנה כדי למנוע בעיית רווחים ב־Windows. [תיעוד mcp-remote](https://github.com/punkpeye/mcp-remote#custom-headers).

<div dir="ltr">

```json
{
  "mcpServers": {
    "escape-race": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "<URL>", "--header", "Authorization:${AUTH_HEADER}"],
      "env": { "AUTH_HEADER": "Bearer <KEY>" }
    }
  }
}
```
</div>

מחליפים רק את `<URL>` ו־`<KEY>`; משאירים את `${AUTH_HEADER}` כפי שהוא. שומרים וסוגרים ופותחים מחדש את Claude Desktop. הגשר יכול להתחבר לשרת מקומי; לחיבור HTTP לכתובת ברשת פרטית מוסיפים `"--allow-http"` למערך `args`.

**Codex CLI:** מפעילים עם שני דגלי ההגדרה הבאים — זה נוסח החיבור שאומת כעובד בפרויקט:

<div dir="ltr">

```sh
codex -c mcp_servers.escape.url="<URL>?key=<KEY>" -c mcp_servers.escape.default_tools_approval_mode="approve"
```
</div>

**כל לקוח MCP אחר:** בוחרים `Streamable HTTP`, כתובת שמסתיימת ב־`/mcp`, והזדהות בכותרת `Authorization: Bearer <KEY>` או בפרמטר `?key=<KEY>`. השרת עובד ללא מזהה חיבור קבוע (`stateless`): שולחים את המפתח בכל בקשה. אין לבחור חיבור SSE ישן; `/api/events` מיועד למסך הצפייה. המשחק עצמו נשמר בשרת לאורך המרוץ.

**שמונת הכלים:** בכל קריאה חובה לשלוח גם `thought`, טקסט של 1–4,000 תווים: הסבר קצר בעברית על הפעולה המתוכננת, שיופיע לקהל. אין לכלול בו מפתחות או מידע אישי.

| כלי | מה עושים | שדות נוספים מעבר ל־`thought` |
| --- | --- | --- |
| `look` | מסתכלים סביב וקוראים את הכללים | אין |
| `inspect` | בודקים חפץ מקרוב | `target` |
| `take` | לוקחים חפץ | `target` |
| `use` | משתמשים בחפץ | `item`, וגם `target` לפי הצורך |
| `enter_code` | מקלידים קוד בכספת | `code`, כמחרוזת |
| `go` | עוברים לחדר סמוך דרך דלת פתוחה | `room`: אחד מ־`lab`, `storage`, `minefield`, `vault` |
| `step` | דורכים על משבצת בשדה המוקשים | `row` בין 0 ל־8, `col` בין 0 ל־6; מספרים שלמים |
| `inventory` | בודקים מה מחזיקים | אין |

בשדות החפצים משתמשים במזהים שהמשחק מחזיר, ולא ממציאים שמות. מבצעים פעולה אחת וממתינים לתשובתה לפני הבאה; ההמתנה המובנית מאפשרת לקהל לראות את הפעולה.

**הודעת פתיחה שאפשר להעתיק לסוכן:**

> אתה מתמודד במרוץ חדרי בריחה. השתמש רק בכלי MCP של המרוץ כדי לחקור, לאסוף רמזים ולצאת מארבעת החדרים. התחל ב־look, קרא את הכללים ואת תשובת כל פעולה והשתמש במזהים שהמשחק נותן. בכל קריאה מלא thought בהסבר קצר בעברית לקהל על מה שאתה עומד לעשות. בצע פעולה אחת בכל פעם והמשך עד שהמשחק מודיע שסיימת. אם המרוץ עוד לא התחיל, המתן להודעת ההזנקה שלי; אחרי איפוס התחל שוב ב־look.

## 5. חשיפת השרת לאינטרנט לשידור החי

**מנהרה חושפת את הפורט לאינטרנט, כולל דפי האתר.** לפני הפתיחה מחליפים את מפתחות ההדגמה במפתחות חזקים, שומרים את `ADMIN_KEY` ואת קישור המנחה בסוד ומוסרים לכל מתמודד רק את המפתח שלו. מסך הצפייה ומצב המשחק ציבוריים. מפעילים את השרת, ואז בחלון פקודות נוסף בוחרים אחת מהאפשרויות:

**Cloudflare Quick Tunnel:** אחרי התקנת `cloudflared`, מריצים; אין צורך בחשבון או בדומיין:

<div dir="ltr">

```sh
cloudflared tunnel --url http://localhost:3000
```
</div>

מתקבלת כתובת HTTPS זמנית. **המנהרה המהירה אינה תומכת ב־SSE**, שעליו מבוססים עדכוני מסך הצפייה: השתמשו בה לחיבור סוכנים ל־MCP, ואת מסך השידור ועמדת המנחה פתחו מקומית. לצפייה מרחוק בדפדפן בחרו חלופה ותבדקו אותה לפני הערב. [פרטים ומגבלות ב־Cloudflare](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/).

**ngrok:** מתקינים, פותחים חשבון ומעתיקים את אסימון החשבון במקום `<NGROK_AUTHTOKEN>`. הפקודה הראשונה נדרשת פעם אחת; השנייה פותחת את המנהרה. [התקנה והתחלה](https://ngrok.com/docs/start).

<div dir="ltr">

```sh
ngrok config add-authtoken <NGROK_AUTHTOKEN>
ngrok http 3000
```
</div>

לכתובת ה־HTTPS שהמנהרה מדפיסה מוסיפים `/mcp` עבור הסוכנים, או `/?mode=live` עבור צפייה מרחוק במנהרה שתומכת בעדכונים. למשל: `https://YOUR-TUNNEL.example/mcp`. עמדת המנחה יכולה להישאר מקומית. אם בחרתם פורט אחר, עדכנו גם את פקודת המנהרה. **בתום הערב סוגרים את המנהרה עם `Ctrl+C` בחלון שלה**, ואז עוצרים את השרת בחלון שלו.

## 6. בדיקות

מתיקיית הפרויקט מריצים `npm test`. הבדיקות מכסות את חוקי המשחק, הבוטים והשרת, כולל חיבור MCP, הזדהות ואיפוס. בדיקות השרת בוחרות פורטים פנויים זמניים וסוגרות אותם בסיום; אין צורך להפעיל שרת מראש.

## 7. מבנה הקבצים

- `DESIGN.md` — תכנון המשחק והחידות.
- `server/server.js` — השרת, חיבורי הסוכנים וניהול המרוץ.
- `server/contestants.json` — שמות, צבעים ומפתחות המתמודדים.
- `server/host.html` — עמדת המנחה.
- `public/engine.js` ו־`public/mock.js` — חוקי המשחק ובוטים להדגמה ולמקומות פנויים.
- `public/index.html`, `public/viewer.js`, `public/style.css` — מסך השידור; `world.js`, `props.js`, `textures.js` באותה תיקייה בונים את התלת־ממד.
- `test/` — הבדיקות; `package.json` — פקודות ההפעלה והתלויות.
